# LiveTrack ML

**Consent-based live location sharing and experimental machine-learning mobility prediction.**

LiveTrack ML is an educational Python web application built with Flask. A participant joins a private room, explicitly agrees to share their location, and grants browser GPS permission. The room administrator can view the latest shared coordinates on a map. A Random Forest regression model demonstrates a short-term next-coordinate estimate from the participant's recent location history.

> **Privacy and accuracy note:** A phone number by itself cannot reveal a person's GPS location. In this project, the phone number is only used as a participant identifier; only its last four digits are stored. GPS coordinates are received from the participant's browser after consent and permission. The ML output is an experimental estimate, not a reliable navigation or tracking prediction.

## Features

- Private tracking rooms generated by the administrator.
- Participant join flow with an explicit consent checkbox.
- Browser Geolocation API for consent-based GPS updates.
- Live room dashboard with Leaflet and OpenStreetMap.
- SQLite storage for rooms, participants, and location history.
- Random Forest model that uses the previous three coordinate pairs to estimate the next coordinate.
- Clearly labelled synthetic route data for ML demonstrations.
- Participant stop-sharing control and administrator data deletion.
- Windows setup launcher (`run_windows.bat`).

## Run locally on Windows

### Option A — Easy setup

1. Install Python 3.10 or newer. During installation, enable **Add Python to PATH**.
2. Download this repository and extract it.
3. Open the project folder.
4. Double-click `run_windows.bat`.
5. Wait for the dependencies to install and Flask to start.
6. Open [http://127.0.0.1:5000](http://127.0.0.1:5000) in Chrome.

Keep the terminal window open while using the application. Press `Ctrl+C` in that terminal to stop the server.

### Option B — Run from a terminal

From the project folder:

```powershell
py -m venv .venv
.venv\Scripts\activate
python -m pip install -r requirements.txt
python app.py
```

Then open [http://127.0.0.1:5000](http://127.0.0.1:5000).

## How to use the demo

1. Open the home page and select **Open admin dashboard**.
2. Sign in with the local demo password.
3. Create a tracking room and copy its invitation link.
4. Open the invitation link in a second browser or Incognito window.
5. Enter a display name and a test phone number, check the consent box, and continue.
6. Select **Allow** when the browser asks for location permission, then press **Start sharing my location**.
7. Return to the administrator's room dashboard to view the participant's latest shared coordinates.
8. Use **Add synthetic demo route** to add clearly labelled sample data and test the ML prediction button.

For a laptop without built-in GPS, browser location can be approximate. The page must remain open while location sharing is active. Browser geolocation requires a secure context (HTTPS) when deployed; `localhost` is supported for local development.

## How the ML demo works

The model is a `RandomForestRegressor` with latitude and longitude as its two output values. For each training example, it uses the previous three GPS coordinate pairs (six numeric input values) to estimate the next coordinate pair. The current implementation waits for at least six recorded points before returning a prediction.

This is a learning demonstration, not a validated forecasting system. Its output can be inaccurate with sparse data, noisy GPS readings, stationary devices, or sudden route changes. The synthetic route is provided so the prediction flow can be demonstrated without collecting somebody else's location.

## Privacy, security, and known limitations

This is a **college prototype**, not a production location-tracking service.

- No phone-number-to-location lookup is performed.
- No telecom carrier location system is accessed.
- Participants must join a room, consent, and grant browser location permission.
- The phone number is not stored in full; the application stores only its last four digits.
- Participants can stop sharing; the administrator can delete a participant's stored location history.
- There is no real SMS OTP verification in this version. The phone number field is an identifier only.
- The local demo authentication and development server are not suitable for public deployment.
- Before public deployment, implement HTTPS, strong per-user authentication, a secure secret key, CSRF protection, rate limiting, room-level authorization, validated retention/deletion policies, and a verified OTP provider if phone verification is required.
- Do not commit real location databases, credentials, `.env` files, or personal information to GitHub.
